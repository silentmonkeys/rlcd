# rlcd_debug_gui —— RLCD 模拟器图形化调试客户端

通过 TCP 连接模拟器（默认 `127.0.0.1:9000`，与 `rlcd_debug` 同一协议），
用**输入框 / 下拉框 / 复选框 / 场景按钮**远程读写 `ui_model` 全部字段、
切页、标注日历。

> 解决"开两个终端太麻烦"的问题：**一个 GUI 窗口完成全部调试**。

## 依赖

仅 Python 3.8+ 标准库（`tkinter` + `socket` + `threading`），无需 `pip install`。

## 用法

```sh
# 终端 1：启动模拟器（带 TCP debug server）
cd simulator && cmake -B build && cmake --build build -j
./build/rlcd_sim

# 终端 2：启动图形化调试客户端
python3 tools/rlcd_debug_gui/rlcd_debug_gui.py
# 连远程/换端口：
python3 tools/rlcd_debug_gui/rlcd_debug_gui.py 192.168.1.5:9000
```

启动后点 **连接** → 即可调试。

## 界面说明

**左右分栏**（中间分隔条可拖动改变左右宽度）：左边是全字段表单，
右边是页面/场景/日历/日志。不再有标签页切换 —— 所有字段在一个可滚动
列表里，鼠标滚轮上下滚。


## 提交模型：改即标脏 + 回车立即发

没有每行的「设置」按钮（原来 22 个按钮全部删掉）：

- **改动即标脏**：输入框改了值 → 背景变黄，底部「应用改动 (N)」显示待发数量
- **回车立即发**：在某个输入框按 `Enter` → 只发这一个字段
- **批量发**：点底部「应用改动 (N)」→ 把所有标脏字段一次发完
- **放弃**：点「放弃改动」→ 重新 `dump` 一次，把控件刷回设备实际值
- **布尔 / 下拉框改了就直接发**，不进脏列表（这类字段没有"输入中间态"）

设备确认 `ok` 之后黄色才消失 —— 黄色 = 还没生效，白色 = 已同步。

## 字段类型

- **Spinbox（数字输入框）**：数值（温度/湿度/风速/电量/堆内存 …），键盘直输精确值
- **下拉框**：天气代码（和风天气 icon 代码 + 中文描述，含 `999` 未知兜底），改即发
- **复选框**：布尔（WiFi 连接 / 充电中 / SD 已挂载 / AP 激活 …），切换即发
- **文本框**：字符串（城市名 / IP / MAC / SSID / 芯片型号 …）

字段共 **48 个 / 7 组**：时间、室内环境、天气、状态栏、设备信息页、
SD·Flash、配网页。完整列表见 `rlcd_debug_gui.py` 的 `FIELD_GROUPS`。

## override 标记与哨兵值

- 字段名前的 **●** 表示该字段已被 override —— 模拟器的自动填充不会再覆盖它。
  点顶部「清除 override」全部恢复自动填充。
- **右键数值框**弹出菜单，可一键填入 `ui_model.h` 的无数据哨兵值：
  浮点 `NaN` / 整数 `UI_INT_NA(-1)` / 温度 `UI_TEMP_NA(-999)`。
  用来测"没数据时画什么"的分支（配合「无数据（哨兵）」场景更快）。

## 场景预设

12 个按钮，每个一次性下发一批字段，用来快速复现极端渲染情况：

| 场景 | 用途 |
| --- | --- |
| 酷暑晴天 / 极寒暴雪 | 温度极值 + 三位数/负号宽度 |
| 暴雨大风 / 雾霾 | 天气图标 + 风速/能见度 |
| 离线（无 WiFi）/ 弱信号 / 满信号 | 状态栏 WiFi 三种画法 |
| 低电量告警 / 充电中 | 电池警示下划线 + 闪电 |
| 无数据（哨兵） | 全字段填哨兵，测空数据分支 |
| 配网模式 | `ap_active=true`，SETUP 页才可见 |
| 无 SD 卡 | SD 未挂载 |

场景下发后会自动隔 650ms 重新 `dump` 一次刷新控件 ——
因为模拟器的 `sim_tick_data()` 是 500ms 一拍，读太早拿到的是旧值。

## 连接说明

采用**持久 TCP 连接**：点「连接」后连一次，全部命令复用同一条连接。
服务端只打印一次 `client connected`，直到点「断开」或关闭窗口才断开。
连接是**非阻塞**的（后台线程连，主线程 `after()` 轮询结果），
连不上也不会卡住窗口；服务端中途挂掉时状态栏会自动翻回「● 未连接」。

## 协议速查

```
set <field> <value>      写字段（自动置 override 位）
get <field>              读字段 → 回 `val <field> <value>`
dump                     读全部字段 → 每行一条 val（「读取全部」用这个）
ovr                      列出当前被 override 的字段名（● 标记来源）
page N / next / prev     切页
mark MM-DD / unmark      日历标注
marks MM-DD,MM-DD,...    批量标注
events MM-DD=xxx;...     预定事件
labels a;b;c             底部标签
clear                    清除 override，恢复模拟器自动填充
help / ping / quit
```

> **帧终止**：每条命令的响应之后模拟器会**再发一个空行**作为帧结束标记，
> 客户端读到空行即可确定一帧读完，不必靠 recv 超时判断结束
> （`dump` 这类多行响应也因此能被正确切分）。
> 这是本次重构补上的 —— 旧版缺这个空行，客户端每条命令都要等满 2s 超时，
> 「读取全部」要 40 多秒，就是所谓的"卡"。

字段表在模拟器侧 `simulator/sim_console.c` 的 `FIELDS[]`，
加字段 = 加一行表项 + 加一个 `OVR_*` 位（见 `sim_console.h`）。
